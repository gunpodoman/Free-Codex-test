# 작업 하네스

## 목적

이 골격은 프로젝트 상태와 반복 작업 절차를 보존해, 이후 개발 요청을 현재 작업 트리에서 이어갈 수 있도록 합니다. 실제 프로젝트 파일과 실행 결과가 작업의 기준입니다.

## 구성

- .agent/state.json: 현재 목표, 활성 요구사항, 남은 문제, 관찰 방법, 복구 위치, 다음 작업을 기록합니다.
- harness/config.json: 하네스가 사용하는 파일 경로, 세션 시작 시 문서를 읽는 순서, 작업 흐름을 정의합니다.
- docs/TASKS.md: 현재 진행하거나 대기 중인 작업을 기록합니다.
- docs/WORKLOG.md: 각 작업 종료 시 완료 내용, 수정 파일, 확인한 사항, 남은 일을 기록합니다.
- docs/HARNESS.md: 이 구조의 목적과 운용법을 설명합니다.

## 작업 시작

1. 프로젝트 루트 AGENTS.md, docs/TASKS.md, docs/WORKLOG.md를 이 순서로 읽습니다.
2. 현재 작업 트리, 사용자 요청, 실제 실행·관찰에 필요한 도구와 의존성을 확인합니다.
3. 실질적인 변경 전에 현재 상태를 보존해야 하는지 판단하고, 적용되는 기본 동작과 대표 사용자 경험을 정합니다.
4. 목표와 다음 우선 작업을 .agent/state.json에 반영합니다.

## 작업 진행과 종료

- 실제 요청을 기준으로 필요한 변경을 진행하고, 결과의 성격에 맞는 실행 또는 직접 검토를 수행합니다.
- 검토 중 발견된 의미 있는 결함만 수정하고, 수정한 결과를 다시 확인합니다.
- 작업을 마칠 때 docs/WORKLOG.md를 갱신하고, 상태가 바뀌면 .agent/state.json과 docs/TASKS.md도 갱신합니다.
- 새 Markdown 파일은 docs/ 안에만 둡니다. 기존 문서는 먼저 읽고 구조를 유지합니다.
- 제품 목표가 주어지지 않았다면 임의의 제품 기능을 만들지 않고, 다음 목표를 작업 목록에 남깁니다.

## Nexus 실행

- Node.js 18 이상에서 프로젝트 루트의 `npm start` 또는 `node server.mjs`를 실행합니다. 별도 패키지 설치 없이 Node.js 기본 모듈만 사용합니다.
- 브라우저에서 `http://127.0.0.1:4173`을 엽니다. `PORT` 환경 변수로 포트를 바꿀 수 있습니다.
- 프로젝트·작업·활동·알림·환경설정은 브라우저의 `localStorage`에 저장됩니다. 설정의 Preferences에서 샘플 데이터로 초기화할 수 있습니다.
- 개발 서버는 앱의 HTML, CSS, SVG, `src/*.js`만 제공합니다. 하네스 파일과 문서 경로는 제공하지 않습니다.

## GitHub 공유 및 Pages 배포

- GitHub Desktop에서 프로젝트 루트 폴더를 저장소로 만들고 `main` 브랜치로 올립니다. `.gitignore`는 로컬 환경 변수 파일, 의존성 폴더, Pages 산출물, OS 파일을 제외합니다.
- 저장소의 **Settings → Pages → Build and deployment → Source**를 **GitHub Actions**로 설정합니다. 이후 `main`에 올릴 때 `.github/workflows/deploy-pages.yml`이 앱 파일만 Pages에 배포합니다.
- 저장소 Pages 주소는 `https://<계정>.github.io/<저장소>/` 형태입니다. 앱 자산 경로는 저장소 하위 경로에서도 작동하도록 상대 경로를 사용합니다.
- Pages 앱은 정적 클라이언트 앱입니다. 각 방문자의 데이터는 해당 브라우저의 `localStorage`에 따로 저장되며, 사용자 간 서버 동기화는 제공하지 않습니다. Pages 사이트는 저장소가 비공개여도 공개될 수 있으므로 공개할 파일을 확인합니다.

## 현재 상태

Nexus 프로젝트 관리 앱을 구현했고 주요 화면과 상호작용을 로컬 브라우저에서 확인했습니다. 프로젝트 루트 `AGENTS.md`는 시작 시 누락되어 있었으며, 새 Markdown 파일은 `docs/`에만 두라는 규칙에 따라 만들지 않았습니다. 지속 상태와 수정 내역은 `.agent/state.json`과 `docs/WORKLOG.md`에서 확인합니다.
